WildClawBench 告诉我们：Agent 评测不该只看模型分数

发表于 2026-06-18 分类于 AI Agent 阅读次数： 本文字数： 2.2k 阅读时长 ≈ 8 分钟
从 WildClawBench 的跨 harness 对比数据出发，讨论 Agent 评测该评什么、Harness 工程为何能拉开 18 个百分点的分差，以及企业如何建立自己的评测门禁。

刷 WildClawBench 榜单时，有一组数据让我停了一下：

同一个模型 MiMo V2 Pro，换一套 Harness，得分能从 29.9% 涨到 48.1%——差了 18.2 个百分点。

这不是模型升级，也不是 Prompt 微调，纯粹是脚手架（Harness）不同。

我在做故障运维 Agent 时也踩过类似的坑：模型没变，中间件链加上工具调用次数限制和死循环检测之后，长任务的成功率肉眼可见地稳了。但要说清楚「稳了多少」，光靠主观感受不够，得有一套能拆模型能力和工程能力的评测框架。WildClawBench 是目前公开数据里，少数把这件事摆到台面上的 benchmark。

先说结论

  1. Agent 评测评的不是「答对了没有」，而是「在真实环境里把活干完没有」——文件有没有生成、状态有没有改对、副作用有没有审计、成本能不能接受。
  2. WildClawBench 最有价值的不是排行榜第一名是谁，而是「同模型、不同 Harness」的对比表——它直接证明：Agent 成绩 = 模型能力 × Harness 设计。
  3. 榜单高分不等于能上线。头部模型在 60 个真实长链路任务上，最高分也才 62.2%。企业还得叠自己的权限治理、合规审计和灰度门禁。

下面按「为什么 Agent 评测更难 → WildClawBench 怎么评 → Harness 数据说明什么 → 我们自己该怎么做」展开。

Agent 评测和 LLM 评测不是一回事

传统 LLM 评测盯的是：输出文本对不对、推理链是否合理。Agent 场景多了一层——模型只是循环里的一环，外面还包着工具路由、上下文裁剪、重试策略、权限边界。

维度 LLM 评测 Agent 评测
核心指标 exact match / judge score 任务完成率 + 轨迹质量 + 副作用审计
交互 单轮或短链路 数十到数百次工具调用
环境 静态输入 浏览器、终端、文件系统会动态变化
安全 较少涉及 越权、泄露、误操作要单独评
效率 通常不考 时延、成本、工具轮次

我在 Noesis 故障运维 Agent 里见过最典型的差异：同样是 read / grep / bash 三个 MCP 工具，模型「说得对」和「真的在节点上查到根因」之间，隔着十几轮工具调用。中间任何一步超时、重复调用、或者上下文被撑爆，任务就漂了——这不是换个大模型能单独解决的。

所以 Agent 评测至少要同时看四件事：Completion（干完没有）、Safety（有没有越界）、Robustness（重跑稳不稳）、Cost（划不划算）。

WildClawBench 在评什么

WildClawBench 是 OpenClaw 生态下的 in-the-wild benchmark：60 个手工任务、6 个类别，跑在真实的 OpenClaw 实例里——真 bash、真文件系统、真浏览器，不是 mock API。

类别 任务数 典型场景
生产力流程 10 论文分类、日程协调、爬取
代码智能 12 无文档代码库推理、调试
社交协作 6 多轮邮件/会议协调
检索核验 11 信息冲突、模糊匹配
创作合成 11 视频剪辑、配音
安全对齐 10 对抗提示、凭证泄露

任务设计上有三个特点，和普通 QA benchmark 不一样：

  • 双语（中英文都有），不是纯英文玩具集
  • 多模态（读 PDF、看视频、剪视频都有）
  • 评的是工作流，不是答题——文件要真的生成，邮件要真的发出去

评分也不是「LLM 判个分就完事」，而是三层混合验证：

验证层 查什么
Deterministic checks 文件有没有生成、改动在不在目标位置
Environment-state auditing 多步流程的副作用和最终状态
LLM/VLM judge 语义上是否满足业务目标

另外，每个任务跑在隔离容器里，ground truth 和评分脚本在 Agent 执行结束后才参与校验——防数据泄漏、防「看过答案再来考」。

最有意思的数据：同模型，换 Harness，分数乱跳

WildClawBench 公开对比了 4 套 Harness：OpenClaw（默认环境）、Claude Code、Codex、Hermes Agent。

四个模型上的得分对比如下（数据来源：官方榜单，2026 年 3 月）：

GPT-5.4

Harness 得分 耗时 (min/task) 成本 ($/task)
OpenClaw 50.3% 5.83 0.33
Claude Code 48.4% 9.07 0.61
Codex 56.8% 7.16 0.57
Hermes Agent 50.7% 8.97 0.44

GLM 5 / MiMo V2 Pro / MiniMax M2.7 上，Hermes Agent 都是最优或接近最优；Claude Code 在国产模型上普遍垫底。MiMo V2 Pro 的分差最夸张：

Harness 得分
Claude Code 29.9%
Codex 35.3%
OpenClaw 40.2%
Hermes Agent 48.1%

汇总一下：

模型 最优 Harness 最差 Harness 分差
GPT-5.4 Codex (56.8%) Claude Code (48.4%) +8.4pp
GLM 5 Hermes (46.4%) Claude Code (31.0%) +15.4pp
MiMo V2 Pro Hermes (48.1%) Claude Code (29.9%) +18.2pp
MiniMax M2.7 Hermes (37.1%) Claude Code (32.0%) +5.1pp

不能简单说「Hermes 全面优于 Claude Code」——GPT-5.4 上 Codex 才是冠军；主榜单头部 Claude Opus 4.7 的 62.2% 跑的是 OpenClaw，压根没出现在 harness 对比子集里。但这组数据足够说明一件事：

你汇报的 Agent 能力提升，可能一半是模型升级，一半是 Harness 换对了。

这也解释了我自己在项目里的观察。故障运维 Agent 加 Harness 中间件链之后，单会话能稳定撑 20+ 轮工具调用、上下文压在 100K token 以内——靠的不是 middleware_intercept 这种日志字段好看，而是死循环检测、悬空 tool call 修复、工具次数上限这些「无聊」的横切逻辑。WildClawBench 用公开数据把这件事量化出来了。

头部模型也没及格，别被榜单忽悠

OpenClaw harness 主榜单上，19 个前沿模型的表现：

排名 模型 总分 总成本
1 Claude Opus 4.7 62.2% $77.40
2 GPT-5.5 58.2% $37.80
3 Claude Opus 4.6 51.6% $81.00
4 GPT-5.4 50.3% $19.80
… … … …
19 Grok 4.20 Beta 19.3% $9.60

最高分 62.2%，意味着 接近四成的真实长链路任务仍然失败。多数模型卡在 20%–50% 区间。

所以 WildClawBench 适合当「外部能力上限对标」，不适合当「上线通行证」。企业真正上线还得过权限边界、合规审计、事故回滚、风险可解释这几关——benchmark 不管这些。

我们该怎么建立自己的评测体系

WildClawBench 再好，60 个任务也覆盖不了你的垂直业务。我倾向 外部 benchmark + 内部任务集 双轨并行，而不是追某一个榜单分数。

日常可以按下面这套分层来跑（实践上的做法，不是 WildClawBench 官方命名）：

层级 做什么 频率
L1 回归 稳定小集，PR 级快反馈 每日
L2 业务仿真 脱敏真实流程镜像 周级
L3 安全对抗 注入、越权、泄漏 周/月
L4 灰度在线 shadow / canary 持续
L5 生产守护 熔断、人工接管率、回滚率 持续

门禁也可以拆成三种，别混在一块：

  • 模型升级：同 Harness 下，成功率升了或成本降了，且安全没退化
  • Harness 升级：同模型下，关键任务涨了，回归集没跌
  • 发布门禁：核心任务成功率过线，安全红线事件为零

WildClawBench 在流程里适合扮演三个角色：外部对标（你在公开高难任务上排第几）、工程诊断（同模型跨 Harness 定位脚手架收益）、版本 sanity check（改完 Prompt/工具策略后快速验一遍）。

我自己在故障诊断场景上的瓶颈也在这里：故障环境构造成本高，Agent 路径不固定，没法像 SWE-bench 那样跑个测试套件就完事。目前靠生产工单回访积累效果，计划对 Top 5 高频故障（节点 NotReady、证书过期、磁盘满等）写轻量注入脚本做回归——这和 WildClawBench 的长链路全集评测是互补关系，不是替代关系。

局限

WildClawBench 也有边界，写清楚免得误用：

  • 60 个任务，垂直行业覆盖有限
  • LLM/VLM judge 有主观性和漂移风险
  • 越真实越难完全复现，越可控越偏离生产
  • Harness 对比只覆盖了 4 个模型，不能外推到全部 19 个

小结

Agent 评测正在从「答案准确率」转向「真实工具链里的任务完成能力」。WildClawBench 的价值，是把 Harness 工程对分数的影响 用数据摆出来了——同模型最多能差 18 个百分点，这不是小数目。

如果你也在做 Agent 项目，我的建议是：

  1. 别只报模型 benchmark 分数，拆开报 Harness 版本和 orchestration 策略
  2. 用 WildClawBench 的跨 Harness 表做对标，但在自己模型 + 自己任务上复测
  3. 把外部 benchmark 当天花板参考，内部业务集 + 安全对抗才是上线门禁
